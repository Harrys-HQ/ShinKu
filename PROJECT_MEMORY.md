## Architecture facts

- Kotlin, Compose plus legacy Android Views in the reader, Voyager ScreenModels, Flow/coroutines, SQLDelight, Coil, OkHttp, WorkManager.
- DI is an Injekt-to-Koin bridge, not exclusively Injekt. `PreferenceStore` currently resolves to `AndroidPreferenceStore` backed by SharedPreferences, despite the architecture document mentioning DataStore.
- Expensive startup dependencies are already initialized asynchronously. Main library transformation runs in `launchIO`; do not describe its `runBlocking` calls as confirmed main-thread freezes.
- API keys are excluded by `PreferenceBackupCreator.isCredential()`; Android OS backup is disabled. Credential storage itself uses the ordinary preference store.
- Predictive loading, upscaling, audio, mood lighting, and blur are optional. Do not assume all are enabled by default.

## Findings to revalidate before implementing

1. Follow-up implementation enables R8/resource shrinking for release and releaseTest, with release lint enabled. See follow-up verification below before assuming production validation is complete.
2. Follow-up implementation adds `ui/browse/feed/FeedRequests.kt`: six overall/three per-source permits shared across the main Discover screen's source calls (updated with owner authorization after the phone comparison), response timeouts after queueing, replaceable refresh/genre jobs, and cancellation-aware state publication. Saved feeds now use one `mapLatest` pipeline triggered by feed changes or refresh, instead of detached duplicate fetches. The separate Suggested Titles screen has not been changed.
3. Extreme cover updates use `Int.MAX_VALUE` limits. Chapter updates already have finite semaphore limits; keep the distinction.
4. Translation disk cache rewrites a whole chapter on each page, has no atomic-write/locking mechanism, and keys only by chapter/language.
5. Library merged download badges and tracker grouping use `runBlocking`; resume deck reads manga/chapters separately for up to five titles.
6. Coil memory cache has a 40% heap ceiling; that is a capacity limit, not a measured allocation or proven OOM.
7. ShinKu settings expose 12 preference groups on one page. Several new UI strings are hardcoded. Existing screenshots show truncated titles/actions/stats.
8. The inspected upscaling interceptor scales bitmaps and sharpens them; its implementation is not neural super-resolution.
9. App baseline is `2.8.1-preview.1` / 143; published docs metadata is `2.8.0` / 142. Treat as preview-versus-stable state pending release intent, not proof of a broken published release.
